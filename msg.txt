Microsoft Foundry provider, web search off by default, bounded loop with failure transcripts

Adds a third reviewer provider for the data-residency path: an open-weight
model (DeepSeek-V4-Pro, Kimi K3, ...) sold and hosted by Microsoft Foundry
inside our own Azure subscription, reached through its OpenAI-compatible
chat-completions endpoint. The model's maker never sees a request, and
Microsoft does not train on or share prompts/completions; with a regional
or Data Zone deployment plus the modified abuse-monitoring exemption,
nothing is stored. .env.example carries the five-step deployment checklist
those guarantees depend on.

vdd/review/model.py
- LLM_PROVIDER=foundry with FOUNDRY_ENDPOINT / FOUNDRY_API_KEY /
  FOUNDRY_DEPLOYMENT, optional FOUNDRY_API_VERSION (Model Inference route),
  FOUNDRY_MAX_OUTPUT_TOKENS (8192; a reasoning model's thinking counts
  against it) and FOUNDRY_EXTRA_BODY (JSON pass-through for model-card
  fields such as thinking controls -- nothing guessed in code).
- Sends Azure's `api-key` header alongside the bearer token so both the
  /openai/v1 and Model Inference routes authenticate.
- A configured Foundry endpoint outranks Gemini/Op
  LLM_PROVIDER still overrides.

vdd/review/graph.py
- Foundry only: bounded loop. A "Tool budget" section in the user message,
  _FinishWithReport middleware that withholds every tool except ReviewReport
  on the last allowed call (FOUNDRY_MAX_MODEL_CALLS, default 8), and a
  ModelCallLimitMiddleware backstop at +2. create_agent binds every turn
  with tool_choice="any" when structured output is requested, so calling
  ReviewReport is the only exit -- a small self-hosted model (QwenTest
  branch, 2026-09-16) never took it unprompted. Gemini/OpenAI are untouched.
- All providers: the agent is streamed instead of
  raises or ends without a ReviewReport logs a per-message transcript table
  and writes <VENDOR>_review_failure_pass<N>.json
  field, passed from pipeline.py) instead of discarding the evidence.
