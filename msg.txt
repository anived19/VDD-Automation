Analyst review workbook (vdd/review_sheet.py -- writer rewritten, reader
and applier unchanged)
  The workbook the analysts were handed was unreadable: 13 columns with the
  software's ids in the middle, frozen panes, and every long evidence note
  clipped to one 15pt line because Excel does not measure row heights for a
  file openpyxl wrote.
  - Review sheet, left to right: Code, Parameter, System value, Meaning,
    Score, Max, Evidence, Analyst value, Analyst note, Preview score. The
    parameter id, source and original value the software reads back are
    still there but hidden (columns K-M); unhide if needed.
  - Every row gets an explicit height from its longest wrapped cell, so a
    five-line evidence note shows as five lines. Calibri 11, thin borders,
    gridlines off, section rows tinted, totals row shaded.
  - No frozen panes on any sheet.
  - The analyst's name is a yellow cell at the top of the Review sheet
    (B3), read back from there; Meta's name cell remains as the fallback so
    older workbooks still work.
  - Score summary (System / Max / Preview per section and total) sits
    between the instructions and the table; title and notes are merged
    across the visible columns.
  - Flags sheet is two columns, "Where" and "Detail", so a parameter id or
    filename is separable from its message; section headers carry counts;
    cross-check items are the full notes, not the 220-character terminal
    cut.
  - Documents sheet: same columns, last one is "Missing fields / reason".
  - Sheet order is the order of work: Review, Entity fields, Documents,
    Flags, then Choices, Audit, Meta.

Report header (vdd/report/render.py location())
  Every report read "Town, <State>": the city label was derived by a
  comma-split heuristic that also split on '/', so on the GST certificate's
  labelled address the fragment 'Town' (from 'City/Town/Village') landed
  as the city. Labelled fields (City/Town/Village, City, Village/Town,
  District, State) are now read directly, with the district standing in
  when there is no city label; the heuristic remains for unlabelled
  free-text addresses. Sri Laxmi Steel: "Hyderabad, Telangana"; B R
  Trading Co: "Belurmath, West Bengal".

LLM review: a note-only correction no longer wipes the value (vdd/review/graph.py)
  A reviewer finding with action=correct, confidence=verified and
  proposed_value=null -- "the wording contradicts the evidence, keep the
  score" -- was applied as Resolved.ok(None): the parameter became
  unresolved and lost its points (Skandan Plastrix, 18-Sep: com_gst_delay_days
  8 days, 3/3 -> 0/3, score 43 -> 40). The value and score are now kept
  and only the note is replaced (recorded as note_only); a null on an
  unresolved parameter or on an entity field is escalated instead. The
  schema tells the reviewer what null means.

Proof of Address: new bucket address_mismatch (config/scoring_model.json,
resolvers.py) -- an addition to the scoring model, analyst request 18-Sep
  addr_ownership_type gains "address_mismatch" -> 0 ("Premises proof is for
  a different address than the GST registration"). When the electricity
  bill resolves to a definite not_match, the rental agreement / bill on
  file proves nothing about the GST-registered premises, so ownership is
  0 instead of the 1 point "rented" carried (or 4 for an inferred "owned").
  A sale deed still wins; a minor discrepancy or an inconclusive
  comparison leaves the usual verdict. addr_rental_validation follows as
  not_match (0); addr_landlord_declaration becomes undeterminable
  (conditional, excluded). The bucket is in the workbook dropdown. The
  electricity-bill resolver now runs before ownership in resolve_all.

Four parser gaps from the Skandan folder
  - Cancelled cheque: "VALID FOR THREE MONTHS ONLY" was read as the account
    holder; the FOR line above the signature wins and validity / payee
    boilerplate is never a name. PRIVATE joins the suffix strip.
  - Names: an initial stands for a word starting with that letter, so
    "NAVIN K" is director "KANNUSAMY NAVIN"; dotted initials ("B.R.") are
    two initials; an initial that is the only difference ("A PERSON" vs
    "B PERSON") is a disagreement.
  - Certificate of Incorporation is its own document type (filename and
    content), parsed for name, CIN, PAN and the spelt-out date of
    incorporation ("TWENTY NINETH day of NOVEMBER TWO THOUSAND TWENTY
    THREE" -> 29/11/2023); the CIN it carries is preferred over any regex
    hit elsewhere; PAN and incorporation date merge from it. It no longer
    files as a PAN card.
  - GST certificate: the registration date under "Date of Validity / From"
    (the current REG-06 layout, where "Date of Liability" is blank) is read;
    Skandan's 02/01/2024 no longer shows as N/A for the reviewer to keep
    re-finding.

Scans with a token text layer (vdd/extract/ocr.py, pipeline.py)
  A page that is mostly one image with under 300 characters of text is a
  scan: Skandan's Factory License (62 characters of e-signature stamp over
  a full-page image) read as digital and was never OCR'd; it is now, and
  its premises address is cut at the PIN code, before the signatory block.
  A scanned, filled-in form whose text layer is only the blank template's
  labels (the KYC form) is re-read by OCR when the expected fields are
  missing and the pages are image-dominated; the better parse is kept
  (method "pymupdf_text+easyocr"). On Skandan's handwritten KYC form OCR
  recovers nothing usable, so it stays POOR -- honestly.

Zigram findings deduplicated (vdd/aml/zigram_screening.py)
